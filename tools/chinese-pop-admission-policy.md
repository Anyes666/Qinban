# 中文流行新批次准入规则 v1

本门只处理未来新增批次；只读来源和证据，不改写、删除或重新标记既有 Songs、catalog.db、EXE 或 UserData。

## 必须全部通过

1. 本地 MIDI 文件必须位于受控根目录，SHA256 与清单 `sourceSha256` 精确匹配。
2. `zh`、`yue` 或 `cmn` 语种须明确核验；本地身份凭证需逐项匹配歌名、歌手、WorkId、EditionId、版本标签、发行日期。
3. 逐曲/版本权利凭证须明确允许**改编**及**桌面软件内置再分发**，记录许可/授权标识、授权来源、审核人、审核日期，并保存哈希绑定的证据副本。仓库代码许可、文件可下载、研究用途、榜单热度或 `candidate-unverified` 均不能替代歌曲谱权利。
4. 至少一份 180 天内的抖音、酷狗或网易云官方榜单凭证；记录歌曲、歌手、排名、日期、官方 HTTPS 来源和本地证据副本 SHA256。P0/P1 编辑标签不算榜单证据。
5. 默认发行日期在近 3 年的版本至少占入选批次 25%；不足则整批 `HOLD_RECENT_DIVERSITY`，不得用旧曲填满。默认每位歌手不超过批次上限 10%（至少 1 首），同一 WorkId 最多 2 个不同 EditionId；已安装来源哈希/EditionId 不重复计数。

## 排序

每个平台只使用最近一份有效榜单凭证，按 `sum(1 / rank)` 降序，其后按平台覆盖数、最佳名次、榜单日期和稳定 ID 排序。先满足近 3 年版本占比，再应用歌手及 WorkId 上限。所有阈值可通过命令行显式调整，并写入报告。

## 运行

```powershell
python tools/select_chinese_pop_batch.py `
  --manifest <候选清单.json> `
  --root <受控来源根目录> `
  --installed-catalog Songs/catalog.db `
  --as-of YYYY-MM-DD `
  --limit 20 `
  --report .validation/<新运行目录>/chinese-pop-admission.json
```

可重复传入 `--manifest` 合并清单。报告路径若已存在，工具拒绝覆盖。`READY` 只表示自动证据门通过；不代表旋律听辨、原神乐器适配或游戏内验收通过。

## 旧候选

缺少逐曲/版本授权或证据的既有候选，保留原谱和原 metadata；仅在独立审计中报告为权利状态未知/未验证，不得通过复制清单、转换谱面或改标签使其进入新批次。


## 2026-10-08 轻量扩充约束

- 本入口的默认选入上限为 **20 首**、单进程；不通过来源证据门时，只写小报告，不执行下载、转换、构建或安装。
- 候选清单合计默认最多 **8 MiB / 1000 条**，单份身份、许可或榜单凭证 JSON 最多 **8 MiB**；超过限制在读取/解析前拒绝，报告默认最多 **8 MiB**，超限不写部分报告。哈希按 **1 MiB** 分块读取。
- CLI 的 `--max-input-mib`、`--max-candidates`、`--max-report-mib` 可显式调整，实际阈值写入 `resourceLimits`；不能静默提高阈值。
- 来源根目录及既有谱库只读，不复制整库，不生成重复发行目录，不下载 SDK；报告使用新的独立路径，不覆盖旧报告。
- 后续转换/安装阶段临时增量工作目录预算为 **256 MiB**，同时只允许一个批次；仅保留新谱、一个当前目录数据库及必要回退信息，不保留重复历史全库。该预算是后续阶段的执行约束，不是当前准入工具对全工作区实施的系统级磁盘配额。
- 已核实旧 `PopBatchTool/BuildRunner.cs` 会把完整 baseline 谱文件逐项 `File.Copy` 到每个输出目录。在完成并验证增量转换适配之前，**不得直接把旧完整基线构建流程当成轻量路径继续运行**。来源准入 READY 也不意味着已经有一条经过验证的轻量入库链路。
- 进程峰值内存必须实测并记录；当前输入限制不等于 Windows 进程级内存硬限制。后续复杂转换若预计峰值超过 512 MiB，需要先缩小批次或另行设计受限转换器，不能以“单进程”冒充峰值保证。
- 本机用户状态、EXE、原谱和原始来源不自动修改或清理。不得为凑新增数量放宽身份/权利/曲风规则，重复 EditionId、来源哈希和曲库已安装项不重新计数。
